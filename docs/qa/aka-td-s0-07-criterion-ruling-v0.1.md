## 1. 事实确认

- 同一「算一次 → 切走 → 切回」命中路径，Rust 微基准（`core.rs::microbench_breakdown`，44 实例）：

  | 分段（520 根） | dev（未优化） | release | 倍数 |
  | --- | --- | --- | --- |
  | ⑥ 整份 `CalcResponse` JSON 序列化 | **27.30ms** | **1.61ms** | **约 17×** |
  | ⑧ 端到端 `calc_indicators`（命中） | 2.54ms | 0.47ms | 约 5.4× |

  release 在**每一个已测分段**上都不慢于 dev；dev 未优化构建下 ⑥ 的量级与 192ms 的坏样本同源。
- 历史坏样本 **229ms / 192ms / 132ms** 均取自**未加 `opt-level` 的 dev 构建**；release 的 ⑥ 仅 1.61ms，物理上跑不出这一量级。
- 修复后（`[profile.dev] opt-level=1` + 埋点句柄复用）同一微基准：⑥ 520 根 `2.338 / 3.453 / 3.794ms`（p50/p95/max），⑧ `1.005 / 4.015 / 6.156ms`；release ⑥ 仍为 `1.61ms`、⑧ `0.47ms`。
- 修复后实机 30 样本批次（`#2–#4`，共 90 个）是在 **`tauri dev`（dev + `opt-level=1`）** 下采集的：`P50 23–24ms`、`P95 33–50ms`、`max 48/58/40ms`，全部 `cacheHit=true`、`matchesCold=true`。
- **release 端到端（UI→IPC→序列化→前端）尚未有 30 样本批次留档**；现有 release 证据只有 Rust 侧微基准 ⑥/⑧。

## 2. 正式判据正文

> **R-S0-07-01｜缓存切回性能判据（构建类型限定版）**

**2.1 适用范围**

- 适用于 `TD-S0-07` 的**热缓存切回路径**：同一指标/参数/数据集先算一次，切走，再切回；命中时 `cache.hit=1`、`engineMs=0`（不重算），序列与冷算逐点一致。
- 不适用于冷启动、冷算（`TD-S0-06`）、首次打开、首装、数据加载、应用启动；这些路径另有判据，不得引用本条。
- 本条只管**耗时**；正确性（`cacheHit`、`matchesCold`/序列哈希）是并行必要条件，任一不成立即未达标。

**2.2 两条构建口径（都必须记录、都必须满足）**

| 口径 | 构建 | 判定线 | 作用 |
| --- | --- | --- | --- |
| **P 线（产品口径）** | release 构建（打包产物 / `cargo build --release`，或发布渠道实际使用的 profile） | `warmMaxTotal ≤ 120ms` | 对外产品性能的**唯一签认口径** |
| **G 线（护栏口径）** | dev 构建且 `[profile.dev] opt-level = 1` | `warmMaxTotal ≤ 120ms` | 更严护栏：dev 在序列化上慢约 17×，G 线过线可提前暴露退化 |

- **判定规则**：P 线与 G 线**同时**满足才可签认；**任一条出现单样本 `>120ms`（严格大于）即未达标**，另一条过线不能抵消。
- `120ms` 整视为合格（判据是 `≤120ms`）；回退条件必须是 `>120ms`，不得写成 `≥120ms`。
- **未测不等于通过**：某条口径没有本协议下的样本，只能记「未测」，不得以另一条口径的数字替代，也不得在汇报中写成「release 已达标」。

**2.3 采样协议与取值方式**

- **样本数**：每条构建口径每批 **≥30 个连续热切回样本**；连续 **3 批（共 ≥90 样本）**。批次之间不得插入冷算、改参数、换数据集或重启应用。
- **判定值**：**`max`（即 `warmMaxTotal`）**，不是 P50、也不是 P95。理由：本条的失效形态是尾部卡顿，用户能感知的是最慢一次；10 样本批次里 P95 就等于 max，用 P95 会把 192ms 的坏样本放过去。
- **记录值**：P50 / P95 / max **三档都要写入留档**；P50/P95 只用于趋势与诊断，不参与判定。
- **样本有效性**：
  - 每个样本必须 `cacheHit=true`、`matchesCold=true`（或序列哈希与冷算相等）；
  - 应用启动后的**首个切回**若为 `cacheHit=false`（冷路径），可标注 `cold=true` 后排除；除此之外**不得剔除任何样本**（含 123ms 这类单点越线样本，必须原样保留）；
  - 压测期间不得有并发 `cargo`/`npm` 构建；需记录机器负载，负载异常（如同机编译、load avg 明显高于常态）时该批作废重跑，不能以「环境噪声」解释越线样本。
- **请求形状固定**：记录 `barCount`（当前 520）、`instanceCount`（当前 50）、`payloadBytes`（当前约 640KB）、指标集合、周期与复权；形状变化视为新口径，必须重采。

**2.4 留档字段（每条批次记录必须齐全）**

`generatedAt`、`commit`、`buildProfile`（dev/release）、`optLevel`、`lto`、`codegenUnits`、`debug`、`targetTriple`、`datasetId`、`barCount`、`instanceCount`、`payloadBytes`、`sampleCount`、逐样本 `totalMs/cacheHit/matchesCold/engineMs`、`P50/P95/max`、机器负载。

- 汇报时数字必须带构建前缀，例如 `release 1.61ms`、`dev(opt=1) 2.338ms`；禁止裸写「27ms」「1.6ms」而不说明构建。

**2.5 构建类型变化导致数字跳变时的处理（本条最关键）**

1. **跨构建不可比**：dev/release、不同 `opt-level`、不同 `lto`/`codegen-units`、不同编译器大版本、不同 target、不同数据集/实例数/报文形状，任何一项变化都构成**口径切换**，不是性能突变，也不是性能改善。
2. **口径切换的处理**：
   - 旧基线冻结为历史，不做跨构建差值结论；
   - 新构建**重新建立基线**，P 线与 G 线都按 §2.3 重采；
   - 不得用「release 比 dev 快 17 倍」证明优化有效，也不得用「dev 从 1.6 变成 27」判性能回归；
   - `120ms` 判定线不随构建类型调整，变的只是用于趋势比较的基线。
3. **跳变排查顺序**：先核对 `buildProfile/optLevel/lto/codegenUnits/target` 与数据集形状，再在同构建、同形状下复跑；只有同构建复跑仍越线，才按性能回归处理。
4. **历史数字标签**：`229/192/132ms` 一律标注「dev（未加 opt-level）」，只能作为根因证据，**不得**作为当前产品性能、也不得作为 release 回归证据。
5. **构建升级不重置判定**：换构建、换编译器、换机器只重置基线，不重置 `≤120ms` 这条线。

## 3. 当前证据挂接（2026-11-07）

| 口径 | 证据 | 结果 |
| --- | --- | --- |
| G 线 dev(opt=1) | `s2-evidence.json` `warm` 30 样本 × 3 批（`#2–#4`），`generatedAt=2026-11-06T16:50:18.641Z` 为入库批次 | **通过**：P50 23–24ms、P95 33–50ms、max 48/58/40ms，全部 ≤120ms，30/30 命中且逐点一致 |
| G 线越线样本 | `#1` 单点 `123ms`（`opt-level=1` 构建刚结束的首启，load avg 8.4，非首切） | 原样留档，不剔除；该批不作通过批次，以 `#2–#4` 连续 3 批为准 |
| P 线 release | `docs/qa/evidence/s2-evidence-p-line-20261107k.json`：release / `opt-level=3` / `lto=false` / `cgu=16` / `debug=0`，90 样本 × 3 批 | **通过**：批 max **89 / 39 / 27ms**，P50 22ms、P95 26ms，全部 ≤120ms；`cacheHit` 90/90、`matchesCold` 90/90 |
| 历史坏样本 | `229ms`（`4ee6ffa` 历史）、`192ms`（`a212660` 原始 JSON）、`132ms`（`7ded2bc` 原始 JSON） | 均为 dev 未优化构建；只作根因证据 |

**结论**：按 `R-S0-07-01`，`TD-S0-07` 已满足 **P 线与 G 线双线通过 → 完整签认（已清偿）**。G 线 dev(opt=1) max 48/58/40ms、P 线 release 批 max 89/39/27ms，两条线全部 ≤120ms。回退条款保留：后续安静机器复跑，任一构建线出现单样本 `totalMs > 120ms` 即回退「部分清偿」，不以偶发/冷启/负载解释豁免。

## 2. 两处取证时序

**抽屉搜索 260ms → 600ms：测试问题，但处置错了**

- 产品侧：`IndicatorDrawer.tsx` 是 200ms 防抖 + `useMemo` 同步过滤 105 条，没有网络/异步计算。正常操作不可能需要 600ms。不是「产品慢一拍」。
- 但 `AC-02.04-02` 卡面写的是「When 等待 **200ms**」。脚本从固定 `sleep(260)` 改成固定 `sleep(600)`，等待越久越容易绿，等于**这条 AC 的时延条件根本没被断言**；产品即使退到 590ms 也照样过。
- 不接受「调大等待就能过」。正确写法是带时间上限的 `waitFor`（如 ≤300ms）；超了就红，红的才是产品/性能问题。当前 600ms 只能算测试抖动，不能作为 `AC-02.04-02` 通过证据。

**PA-17 改 50ms 轮询：可接受**

- `handleRestoreDefaults` 同步 `setParams` + `setAppliedParams`，DOM 下一帧更新；点击后立刻读输入框会读到旧值，属测试读帧问题。50ms 轮询 + 最终仍断言 `12/26/9`，没有放宽断言。
- `AC-02.05-04（补3）` 本身没有 200ms 时限，轮询合法。
- 但 `8b399c8` 的提交说明把「副图提示与 ParamPanel 差一帧」混进了抽屉搜索的理由，两个套件的事混成一条，属说明不实。

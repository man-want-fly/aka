## 0. 结论（先看这 6 行）

1. **下一 Sprint 只做一件事：Sprint 0 地基**（DateRange 改造 + CI/黄金回归 + `state.db` 与 manifest 契约），15 人日；不做新指标、不做新页面。

3. Sprint 0–12 共 13 个双周 Sprint，计划 **247.6 人日**；对 260 名义容量留 **12.4 人日缓冲**（4.8%）。
4. 扣除法定节假日/评审约 10 人日后，真实缓冲仅约 **2.4 人日**，排期属于「紧但可交付」；返工风险必须靠 B6 的 beta 策略和口径内容提前介入吸收。
5. P1 21 个指标与 Story `S-01.03-01`（2.5 人日）**不进入** 26 周计划，MVP 后单独排 4 周。
6. 唯一推荐并行方式：B1 完成后 **B2 与 B3 双流并行**；B4 与 B5 在 S5 并行；B6 收口。共享内核 API 在 B1 结束即冻结。

## 2. 指标分批方案（P0 84 个）

### 2.1 分批原则

1. **先底座后被派生**：EMA/Wilder/滚动窗口/OLS 一次实现，供 DEMA、TEMA、MACD、PPO、TRIX、TSI、ATR 系列、LinReg 系列复用；不按指标名逐个造轮子。
2. **同类公式归并**：均线族、通道族、ATR 止损族、量能族、横截面族各自共享内核；同一批内先做「被依赖项」，再做包装项。
3. **窗口类集中处理**：所有 `O(n·k)` 的滚动窗口（MA、HHV/LLV、StdDev、LinReg、Correlation、广度 250 日）统一走增量/前缀和/滑窗内核，B1 一次性定框架，避免后期逐个优化。
4. **口径存疑后置**：P0 中 6 个「部分」口径（T07 KAMA、M07 MACD-V、M11 TRIX、M17 TSI、D07 EOM、E02 RS 分位）集中到 **B6**，注册表标 `spec_status=Partial` + UI `beta` 徽标；13 个 P1「部分」与 8 个「beta」全部留在 MVP 之后。
5. **一批一验收**：每批必须有「黄金用例全绿 + 性能达标 + 口径页非空 + 可上图」四件实物，禁止半成品跨批堆积。

### 2.4 每批验收标准（统一，不允许「口头完成」）

| 维度 | 标准 | 证据 |
| --- | --- | --- |
| 黄金用例 | 每个 id ≥ 1 组确定性夹具（mock 固定 seed，520 根）；**价格/金额类**相对容差 `1e-6`；**振荡/比率类**绝对容差 `1e-4`；**广度计数类**必须整数完全相等 | `indicator-golden` 报告：`84/84 passed`，失败附首个偏差下标 |
| 参照对象 | 主参照 = 公开公式的手工/表格夹具；每批抽 3 个代表指标与 TradingView 或通达信样本对照并留截图；B6 的 6 个 ◐ 指标双人复核 | 批验收附件 `golden-report-bX.md` |
| 预热 | 首个有效值下标 == 注册表 `warmup`；预热区必须为 NaN/断线；停牌/零量按 D-19/D-21 返回 NaN | 单测断言 |
| 性能 | 520 根单指标 p95：简单 ≤ 1ms、复杂 ≤ 3ms；5 实例批量 ≤ 10ms；工作台冷算 6 实例 ≤ 300ms（`S-02.06-01`）；改参 ≤ 120ms（`S-02.05-01`）；缓存命中 ≥ 85%（PRD D-06） | 引擎埋点 + 前端页脚统计 |

| 口径 | 该批每个 id 的口径页四段非空、0 占位；B6 允许标 `beta` 但必须写明不确定点 | 口径页清单逐条勾选 |
| 集成 | 可在工作台添加/替换；参数面板按 `ParamSpec` 渲染；页脚显示 id/参数/复权/数据集版本 | 5 分钟演示录屏 |
| 回归 | 本批全绿 + 之前批次全绿；`cargo test` 与前端 `build` 在 CI 通过 | CI 链接 |

**「一批完成」判定（8 条全满足才算完成）**：① 该批 id 全部实现且注册；② 黄金报告全绿；③ 性能门槛达标；④ 口径页该批全覆盖；⑤ 工作台可上图/可改参；⑥ 无 `TODO(sprint-*)` 遗留；⑦ 回归无红；⑧ 代码已评审合并并留演示。任一不满足 → 批次不计完成，不启动下一批（可并行批除外）。

### 2.5 并行与 2 FTE 分配假设

- **假设**：2 名全职、全栈（Rust + React），其中 A 主 Rust 评审、B 主前端评审；口径内容 18 人日计入 Story，由两人分担（若由产品/研究独立撰写，则释放 18 人日为缓冲）。
- **并行窗口**：
  - S1：A 做 B1，B 做 `S-02.02-01/02`（周期/复权）。
  - S2–S3：A 做 B2，B 做 B3；**B1 结束后冻结内核 API**，注册表按 append-only 分文件，避免同一文件冲突。
  - S4–S5：A 做 B4，B 做 B5；两者只共享 `OhlcvView` 与横截面快照读接口。
  - S6：两人合做 B6 + 抽屉/目录集成（B6 需双人复核）。
- **不并行项**：注册表 id 迁移（S0）、缓存键变更（S5）、口径页终审（S12），必须单点负责。

### 2.6 ◐ / ○ / P1 的处理

- P0 中的 **6 个 ◐**：全部进 B6，标 `Partial + beta`；不影响 B1–B5 的主链路。
- 其余 **13 个 ◐** 与 **8 个 ○（beta）**：全部属于 P1 21 个，不进 MVP 26 周；MVP 后单排 4 周（引擎约 14 人日 + 口径约 5 人日 + P1 Story 2.5 人日）。
- 目录只展示已实现项（PRD D-05/D-23），P1 未完成不占位。

### 3.3 下一 Sprint 的唯一推荐

**Sprint 0（地基）**：DateRange + CI/黄金回归 + `state.db`/manifest 契约 + 性能基线，15 人日。  
理由：B1–B6 的缓存键、口径页、黄金用例都建立在日期区间与数据集版本之上；E-01/E-06/E-07 又依赖 `state.db`。晚一个 Sprint 做，至少造成 3 处 DTO/测试返工，且 84 个指标的回归无法自动防退化。

### 3.4 关键路径（延误即拖垮整体）

1. **S0 DateRange + manifest 契约** → 阻塞 S1 周期/复权、S4/S5 缓存、S8 自选持久化。
2. **S0 黄金夹具 + CI** → 阻塞每一批的完成判定；没有它，B1–B6 无法验收。
3. **B1 内核冻结** → 阻塞 B2/B3 并行；B1 延误会顺延全部引擎批次。
4. **84 份口径页 18 人日**（S7–S12）→ 发布门禁 2「84 份四段非空、0 占位」，是唯一无法用加班压缩的内容型关键路径；必须从 S7 第一周启动，不能留到 S12。
5. **首装 `S-07.03-01` 8 人日**（S10）→ 依赖 manifest/重建/空错态，单条最大，晚到会挤压 S11/S12。

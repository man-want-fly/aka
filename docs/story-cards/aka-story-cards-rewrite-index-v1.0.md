### EP-05 改写要点

1. 原 `S-02.06-01`（批量按需计算与冷算性能，5 点）一张卡塞了三件事（批量、区间、序列装配），按规则「一个 Story ≈ 1–5 点、能独立演示」拆成 `01 / 06 / 08` 三张。
2. 原 `S-02.06-02`（缓存命中 / 世代丢弃 / 旧结果不渲染，4 点）混了后端缓存与前端丢弃，拆成 `02 / 03 / 04 / 05` 四张，**「旧结果不渲染」移交 EP-07**（前端 generation 比对，`WorkbenchPage.tsx:583/820/861`）。
3. 原卡「世代丢弃」写作后端职责，代码事实是：后端 `CalcResponse.dataset_generation` 只回显，无任何丢弃逻辑；丢弃在前端 `generation` ref。此口径已在新卡中改正。
4. 删除原卡所有「`CalcCacheKey` 结构体」「六元组缓存键」「`kernels/` 子目录」「`BarFlag`」表述，改为 `calc_key()` 字符串、7 维 + 区间、`kernels.rs`、`Vec<String>`。
5. 新增卡依据代码缺口：`calc_cache` 无上限无淘汰（`core.rs:317` 只有 `Mutex<HashMap>`），见 `S-EP05-05`；`QualityFlag` 8 变体无线上字符串冻结测试，见 `S-EP05-07`；DTO 无 wire 形状测试，见 `S-EP05-09`。

### EP-06 改写要点

1. 原 6 张 `S-IPC-01…06` 全部保留主题，但**全部换成可执行断言**：原卡只写「列清单」「核对一致」，新卡写成「46 / 41 / 5 的三向比对 + 脚本退出码」，否则开发期无法致红。
2. 新增 `S-EP06-07`：代码里存在真实缺陷 —— `ParamValue` 的 `#[serde(untagged)]` 让 `20` 与 `20.0` 落成不同变体，`calc_key` 的 `params_json` 因此分裂（`core.rs:2279`），跨请求缓存永不命中。这不是「补测试」，是修 Bug。
3. 原卡「三套错误码」与代码不符，实为**四类形状**：`ErrorCode` 13 值（`E_` 前缀）/ `DatasetErrorCode` 5 值（无前缀，仅字段）/ `SimErrorInfo.code` 10 个自由串 / 2 条 `Result<_, String>` 裸串错误。按事实写，不迁就原卡标题。
4. 原卡「前端六模块」与代码不符：实际是 **8 个 `pages/` 目录 + 9 个 `features/` 目录**，且全仓只有 1 处 Tauri import。按目录实数写。
5. 原卡「旧命令处置」没有可处置对象：架构文档列的 6 条「规划（未注册）」命令在代码里一条都没有，且文档还写着「只注册了 4 条」（实为 46）。本卡改为**修文档**，并明确「不得为对齐文档去补实现」。
6. 删除原卡所有「大载荷改用 arrow / 二进制 / 分页」的开放选项，改为写死「全 JSON + 2 MiB 硬阈值 + 超限只埋点」，并列出被拒的三条替代路线及理由。
